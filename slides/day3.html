The 2026 consensus

Agent = model + harness

  • Anthropic, Effective harnesses for long-running agents (Nov 2025); OpenAI, Harness engineering (Feb 2026); Birgitta Böckeler on martinfowler.com (Apr 2026): agent quality lives as much in the harness as in the model.
  • LangChain raised its Terminal-Bench 2.0 score from 52.8 to 66.5 by changing only the harness, same model.
  • So the question "which model?" comes with a second one: "in which harness?"
A useful split (Böckeler, 2026)

Guides steer before the action; sensors check after it

Guides (feed-forward)

  • System prompt and AGENTS.md
  • Tool names, descriptions, enums
  • Skills and examples
  • Permissions that make wrong actions impossible

Sensors (feedback)

  • Tests, type checkers, linters
  • Tool errors that say what to do next
  • Evals and LLM reviewers
  • Traces and audit logs for humans
Rule of thumb: guides make the right action likely; sensors make the wrong one visible fast enough to fix. A harness with only guides is hope; with only sensors it is expensive.
Harness 1 · Pi (Mario Zechner and contributors, MIT, ~117k stars)

Pi: the minimal coding-agent harness

  • Four default tools: read, bash, edit, write (+ grep, find, ls on request).
  • A short system prompt in named sections: preamble, tools, rules, docs, project context (AGENTS.md / CLAUDE.md), skills, cwd.
  • Sessions as a JSONL tree you can branch and fork; compaction inserts a summary entry.
  • Interfaces: terminal UI, --print, --mode json events, --mode rpc, a TypeScript SDK. MCP built in since 1.x.
  • OpenClaw is built on it.

From Pi's own docs: it "does not ask for approval before every tool call" and has no built-in sandbox. Run it in a container or VM.

Harness 2 · OpenClaw (MIT, ~393k stars)

OpenClaw: an always-on personal agent

  • Gateway: a long-running daemon that hosts the agent (Pi's loop) and its sessions.
  • Channels: talk to it from WhatsApp, Telegram, Slack, Discord and more.
  • Heartbeat: it wakes up on a schedule and acts without being asked.
  • Files as personality and memory: SOUL.md, AGENTS.md, MEMORY.md.
  • ClawHub: a public registry of skills.
  • OpenRouter: openclaw onboard --auth-choice openrouter-api-key.

2026: the agent-security case study

CVE-2026-25253: a crafted link could leak the gateway token and hand over the agent. "ClawHavoc": 341 malicious skills on ClawHub. Thousands of gateways exposed to the internet.

The lesson

Autonomy + private data + outside input + one public registry = the lethal trifecta at scale (Day 4).

Harness controls in your loop

Three control points between the model and the world

def policy(name, args):          # allow | ask | deny
    if name in m.READ_TOOLS:  return "allow"
    if name in m.WRITE_TOOLS: return "ask"
    return "deny"

def guard(name, args):           # before_tool: block
    if name == "send_email" and args["to"] not in EMAILS:
        return '{"error": "Blocked: not a registered email"}'

def audit(name, args, result):   # after_tool: log
    AUDIT.append(redact({"tool": name, "args": args}))

K.run_agent(task, tools, permission=policy,
            approve=ask_officer, before_tool=guard,
            after_tool=audit)

Permission

Per tool: allow, ask a human, or deny. Claude Code's permission modes and Pi's tool allowlists are this.

Hook before

Code that inspects arguments and can block. Encodes rules a tired approver might miss.

Hook after

Redact, trim, log. An audit trail outside the model's reach.

Claude Agent SDK (claude-agent-sdk)

The Claude Code harness as a library

  • The loop, built-in tools (files, shell, search, web), permission modes, hooks (before/after tool use), sub-agents, skills, MCP and compaction, from the harness Anthropic ships as Claude Code.
  • You add custom tools (in-process MCP servers), a system prompt and a permission policy.
  • Built for Claude models; it speaks the Messages API.
When to pick it: agents that work on files and code like a developer would. When not: narrow service agents like Rafeeq with a handful of business tools, where most of the harness is unused surface.

The vendor runs the loop

OpenAI Agents API and Claude Managed Agents

OpenAI Agents API (beta, Sep 2026)

  • Agents as stored objects with tools, instructions and versions.
  • Runs with sessions, tool approvals and hosted tools, on OpenAI's infrastructure.
  • Successor to Assistants (shut down Aug 2026) and Agent Builder (Nov 2026).

Claude Managed Agents (beta, Apr 2026)

  • Anthropic runs the loop and a per-session container where tools execute.
  • Versioned agent configs, sessions with an event stream, skills and MCP.
  • Vaults keep credentials out of the sandbox; outcomes grade the agent against a rubric; schedules.
  • Sessions are stored by Anthropic: not eligible for ZDR (overview).
Questions before you buy: where do sessions, files and logs live (PDPL, data residency)? Can you export traces? Which models can you use? What happens to your agent when the beta changes?

When one context window isn't enough

Long tasks fail in predictable ways

Doing too much at once

The agent starts five things, runs out of context halfway, and the next session finds a half-built mess.

Declaring victory early

"All tests pass" after running one file; "fixed" without running anything.

Forgetting

Compaction kept the summary, lost the detail that mattered.

Anthropic's harness for long-running agents (Nov 2025):

  • An initializer run writes a feature list (JSON) and a progress file.
  • Each coding run reads them, does one feature, tests it end to end, commits, and updates the progress file.
  • State lives in the repository: git history, the feature list, the progress notes.
Geoffrey Huntley, 2025

The Ralph loop

while :; do cat PROMPT.md | claude-code ; done
  • Fresh context every iteration: no rot, no stale plans; you can change the model or the harness between iterations.
  • State outside the model: the code, PROGRESS.md, git.
  • Back-pressure: tests, types, linters tell each iteration where it stands.
  • One thing per iteration, then stop.
for i in range(1, max_iters + 1):
    tests = run_tests(repo)
    history.append(tests["failed"])
    if tests["failed"] == 0:      stop("success")
    if stalled(history, patience): stop("no progress")
    if spent > max_cost:           stop("budget")
    prompt = PROMPT.format(failures=tests["summary"])
    run_agent(prompt, coding_tools(repo))  # fresh
    git("add", "-A"); git("commit", "-m", f"ralph {i}")
Keep the sensor honest

Tests only push back if the agent can't edit them

  • The rule is in AGENTS.md (a guide) and in edit_file (a hard constraint). Models under pressure do rewrite tests.
  • Review the loop's diff, not its transcript: did anything under tests/ change?
  • A passing test suite is back-pressure, not a specification. Some fixes satisfy the test and miss the policy.
Designing the loop

Exits, checkpoints, and who checks the maker

Four exits

Success · iteration budget · no progress (failures haven't fallen for n iterations) · cost or time budget.

Checkpoints

Commit after every iteration: you can diff, bisect, roll back, or restart from any point.

Maker and checker

A second agent (or a different model) reviews each diff against the policy before the loop continues.

The loop is harness-agnostic. uv run loops/ralph.py --harness pi runs the same outer loop with Pi inside. Osmani (Loop engineering, Jun 2026): the loop, not the single run, is the unit you design and measure.

Reliability

pass@k asks "can it?"; pass^k asks "will it, every time?"

  • pass@k: at least one of k trials passes. Right for tools where a human picks the best attempt (code suggestions).
  • pass^k: all k trials pass. Right for a citizen-facing agent: each citizen gets one attempt.
  • If one trial passes with probability p, independent trials give pass^k ≈ pk: 90% per trial is 73% over three.
  • τ²-bench reports pass^k for this reason.

Read the failures

Error analysis beats a dashboard

  1. Run the suite; collect every failing trial with its transcript.
  2. Read them. Write one root cause per failure in plain words.
  3. Group the causes; count them.
  4. Fix the biggest group with one change (prompt, tool, context, model).
  5. Re-run. Check what flipped in both directions.
Root causeTypical fix
wrong factretrieval, tool description

grader too strictfix the grader, not the agent
