01
Rules

Individual, public, evidenced

Individual work

Each learner submits their own project. A public GitHub repository before the Day 5 deadline: no zips, no Drive folders, no private repos.

AI assistants allowed

For writing the code. You own every design decision, number and claim; anything the README claims must be backed by code or saved outputs.

README, not a talk

The README is the presentation. Instead of a live run, the repo shows evidence of real runs.

Evidence of real runs: eval CSVs for both configurations, plus logs or traces, a transcript, screenshots or a short screen recording. Synthetic or public data only.
Suggested structure

What the README explains

  1. Problem and user: who asks what, and what "done" looks like
  2. Evidence of real runs: a transcript of one multi-step task with tools and an approval, plus logs or traces
  3. Design across the ladder: prompt, context, harness, loop, graph; which rungs you needed and why
  1. Evals and error analysis: A vs. B on 15+ tasks; the biggest failure category; what flipped
  2. Security: your trifecta, one attack, the defence that stopped it, in code

Scoring guide

What each criterion looks like at its best

CriterionWeightStrong evidence
Working system (code + saved run evidence)25%A multi-step task with 3+ tools (one over MCP) runs from a clean clone; eval CSVs, logs or traces, a transcript or recording show real runs, including an approval
Context and harness engineering25%A spec or AGENTS.md, memory or retrieval, a compaction or budget rule; permissions and budgets; each choice justified
Evaluation and error analysis20%15+ tasks with automatic graders, two configurations with saved CSVs, root causes counted, one change explained by the data; judged from the README and the files it points to
Security, governance and operability20%Trifecta mapped; an attack that worked before the defence and not after; defence enforced in code; PDPL considered; traces or logs
Presentation and reproducibility (README.md)10%The README is the presentation: problem, ladder design, A vs. B, security note, and the course link; a stranger can run it with uv run and a key

The README must include this line exactly; without it you lose part of the presentation mark:
[Advanced Agentic AI Systems Engineering - SDAIA Academy](https://github.com/sdaiaacademy/agentic-ai/)

The reader's questions

Questions your README should answer

  • Why an agent here and not a workflow (or the reverse)?
  • What's in the context on turn 10? How many tokens, and what did you cut?
  • Which tool call would you least like the model to get wrong? What stops it?
  • Your pass rate went from A to B. Is that difference bigger than the noise? What's pass^k?
  • Show me an injection that worked before your defence. Does the defence depend on the model?
  • Where does personal data go: which provider, which country, which logs?
  • What happens when the free model disappears tomorrow?
  • What does one conversation cost at 1,000 users a day?
Great answers point to a trace, an eval row, a line of the harness or a test. "We didn't handle that, and here's how we would" is a fine answer too.
Sessions 2–4

Polish and submit checklist

  • Re-run your eval on A and B; paste the table into your README
  • Save the evidence: both eval CSVs, logs or traces, a transcript, screenshots or a short recording
  • Every number in the README traces to a saved file
  • Re-run your attack against the defended version
  • Clean-clone test: does uv run work from the README alone?
  • No keys in the repository; .env is ignored
  • README: problem, ladder, A vs. B and error analysis, security note, course link
  • Push the public repository before the deadline; send the link

Instructor review

Patterns across projects

What worked

  • Starting from the eval tasks, then building
  • Rules in code, judgement in the model
  • Defences that block in the harness, shown with a trace
  • One change between A and B, explained by the failures

What to watch

  • Twenty tools where five would do
  • "The model will follow the system prompt" as a security plan
  • Scores without transcripts, or one trial reported as reliability
  • README claims with no saved run, CSV or trace behind them
