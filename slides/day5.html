Scoring guide

What each criterion looks like at its best

CriterionWeightStrong evidence
Working system and live demo25%A multi-step task with 3+ tools (one over MCP) runs live from a clean start; an approval is shown
Context and harness engineering25%A spec or AGENTS.md, memory or retrieval, a compaction or budget rule; permissions and budgets; each choice justified
Evaluation and error analysis20%15+ tasks with automatic graders, two configurations, root causes counted, one change explained by the data
Security, governance and operability20%Trifecta mapped; an attack that worked before the defence and not after; defence enforced in code; PDPL considered; traces or logs
Presentation and reproducibility10%On time; the README lets a stranger run it with uv run and a key
Technical Q&A

Questions you should be ready for

  • Why an agent here and not a workflow (or the reverse)?
  • What's in the context on turn 10? How many tokens, and what did you cut?
  • Which tool call would you least like the model to get wrong? What stops it?
  • Your pass rate went from A to B. Is that difference bigger than the noise? What's pass^k?
  • Show me an injection that worked before your defence. Does the defence depend on the model?
  • Where does personal data go: which provider, which country, which logs?
  • What happens when the free model disappears tomorrow?
  • What does one conversation cost at 1,000 users a day?
Great answers point to a trace, an eval row, a line of the harness or a test. "We didn't handle that, and here's how we would" is a fine answer too.
The next 35 minutes

Final prep checklist

  • Re-run your eval on A and B; paste the table into your README
  • Run the demo once (warms the response cache); time it
  • Record a 2-minute screen capture as a backup
  • Re-run your attack against the defended version
  • Clean-clone test: does uv run work from the README alone?
  • No keys in the repository; .env is ignored
  • Slides: problem, demo, ladder, evals, security
  • Tell the instructor if you'll present as a pair

Patterns across projects

What worked

  • Starting from the eval tasks, then building
  • Rules in code, judgement in the model
  • Defences that block in the harness, shown with a trace
  • One change between A and B, explained by the failures

What to watch

  • Twenty tools where five would do
  • "The model will follow the system prompt" as a security plan
  • Scores without transcripts, or one trial reported as reliability
  • Demos that only work with a warm cache on the presenter's laptop
